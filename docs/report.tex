\subsection{Περιορισμοί που εξασφαλίζουν την Ορθότητα}

Η βάση δεδομένων εφαρμόζει τέσσερα επίπεδα ελέγχου ακεραιότητας:
\emph{οντότητας}, \emph{αναφορικής}, \emph{πεδίου} και
\emph{επιχειρησιακής λογικής}.  Στα επόμενα καταγράφονται όλοι οι
απαραίτητοι περιορισμοί.

\subsubsection*{1.~Ακεραιότητα Οντοτήτων (Entity Integrity)}
Κάθε πίνακας διαθέτει τεχνητό \texttt{PRIMARY~KEY}
(\texttt{INT~AUTO\_INCREMENT}).  Πλεονεκτήματα:
\begin{itemize}
  \item σταθερό μήκος κλειδιού $\Rightarrow$ μικρότερα δευτερεύοντα
        ευρετήρια,
  \item αποσύνδεση από επιχειρησιακά πεδία που μπορεί να αλλάξουν
        (π.\,χ.\ αλλαγή προτύπου barcode).
\end{itemize}

\paragraph{Συμπλήρωση.}
\textbf{NOT NULL} προστέθηκε στα \texttt{coordinates},
\texttt{tech\_equipment} και σε όλες τις στήλες ημερομηνίας, ώστε να
αποτρέπεται η μηδενική τιμή \texttt{0000‑00‑00}.

\subsubsection*{3.~Ακεραιότητα Πεδίου Τιμών (Domain Integrity)}
\begin{itemize}
  \item \textbf{Τύπος–εύρος:}
        \texttt{CHECK(birth\_date~\textless=~CURDATE())},
        \texttt{CHECK(formation\_date~\textless=~CURDATE())},
        \texttt{CHECK(festival\_year BETWEEN~1970 AND~YEAR(CURDATE()))}.

  \item \textbf{Consistency:}
        \texttt{CHECK(end\_date~\textgreater=~start\_date)} προστέθηκε
        και στον πίνακα \texttt{Festival}.
\end{itemize}

\subsubsection*{4.~Μοναδικότητα (Unique Constraints)}
\begin{itemize}
  \item \texttt{ean\_code}: προστέθηκε \texttt{UNIQUE} για αποφυγή
        διπλού barcode.
  \item \texttt{Artist(real\_name,~birth\_date)}:
        αποτροπή διπλοκαταχώρισης καλλιτέχνη.
  \item \texttt{Band(band\_name,~formation\_date)}:
        αντίστοιχα για συγκροτήματα.
  \item Πίνακες:
        (\texttt{Artist\_Band}, \texttt{Performance\_Artist},
        \texttt{Stage\_Staff}) χρησιμοποιούν σύνθετο \texttt{PRIMARY~KEY}.
\end{itemize}

\subsection{Mock data}

Για την παραγωγή ρεαλιστικών δειγματικών δεδομένων χρησιμοποιείται
το script \texttt{data.py} με τις εξής βασικές παραμέτρους:

\begin{itemize}
  \item \textbf{Πλήθος οντοτήτων:}
        \begin{tabular}{@{}ll@{}}
          \texttt{NUM\_LOCATIONS}       &= 10 \\
          \texttt{NUM\_FESTIVALS}       &= 10 \;(\,έτη 2017–2026\,)\\
          \texttt{NUM\_STAGES}          &= 30 \\
          \texttt{NUM\_EVENTS}          &= 50 \\
          \texttt{NUM\_PERFORMANCES}    &= 100 \\
          \texttt{NUM\_ARTISTS}         &= 30 \\
          \texttt{NUM\_BANDS}           &= 20 \\
          \texttt{NUM\_VISITORS}        &= 200 \\
          \texttt{NUM\_TICKETS}         &= 300 \\
          \texttt{NUM\_STAFF}           &= 30 \\
          \texttt{NUM\_RATINGS}         &= 400 \\
          \texttt{NUM\_RESALE}          &= 50 \\
          \texttt{MAX\_TRIES}           &= 20  % προσπάθειες για το scheduling performances
        \end{tabular}

  \item \textbf{Determinism:}  
        \texttt{Faker.seed(42)} και \texttt{random.seed(42)} για
        επαναληψιμότητα των αποτελεσμάτων.

  \item \textbf{Μοντέλο γενεαλογίας μουσικών ειδών:}
        Ορίζεται dict \texttt{GENRES} με κύριες κατηγορίες
        (\emph{rock, jazz, pop, hip-hop, electronic}) και υπο‐είδη,
        ώστε οι στήλες \texttt{music\_genre} / \texttt{sub\_genre} να
        προέρχονται από πραγματικά αναγνωρίσιμα ζεύγη.

  \item \textbf{Ειδικοί κανόνες για seed-σενάρια (Q3, Q7, Q9, Q14):}
        \begin{enumerate}
          \item \emph{Seed 3:} Τουλάχιστον 3 \textbf{Events} στο
                Festival \#1 (\texttt{MIN\_EVENTS\_F1=3}), ώστε
                Artist \#1 να έχει τρεις warm-up εμφανίσεις.
          \item \emph{Seed 7:} Σε κάθε Festival να υπάρχει
                τουλάχιστον 1 \emph{tech} staff (role="tech") σε
                κάποιο Stage–Staff.
          \item \emph{Seed 9:} Οι επισκέπτες \#1 και \#2 παίρνουν
                τουλάχιστον 4 performances στο παλαιότερο έτος.
          \item \emph{Seed 14:} Ισορρόπηση rock εμφανίσεων:
                \(\ge\) 3 σε κάθε ένα από τα έτη 2023 και 2024.
        \end{enumerate}

  \item \textbf{Επιπλέον έλεγχοι:}
        \begin{itemize}
          \item Διασφάλιση κενών $\ge$ 5 min και διάρκειας 30–180 min
                μεταξύ Performances (μέσω \texttt{MAX\_TRIES} loop).
          \item VIP tickets $\le$ 10 \% capacity ανά event (δυναμικά).
          \item Trigger \texttt{trg\_staff\_quota} απενεργοποιείται μόνο
                κατά το \texttt{LOAD DATA} με \texttt{@bulk\_load=1}.
        \end{itemize}

  \item \textbf{Ρουτίνα φόρτωσης CSV:}  
        Το script παράγει 12 αρχεία CSV στον φάκελο
        \texttt{csv\_data/}.  Το \texttt{load.sql} πράττει:
        \begin{enumerate}
          \item \texttt{SET FOREIGN\_KEY\_CHECKS=0;}
          \item \texttt{TRUNCATE} όλων των πινάκων.
          \item \texttt{LOAD DATA INFILE ... IGNORE 1 LINES}
                με \texttt{"\textbackslash N"} για NULL τιμές
                στα προαιρετικά FK.
          \item \texttt{SET FOREIGN\_KEY\_CHECKS=1;}
        \end{enumerate}

  \item \textbf{Self-test:}  
        Στο τέλος τρέχει η συνάρτηση \texttt{\_self\_test()}, η οποία
        ρίχνει AssertionError αν κάποιο seed‐σενάριο αποτύχει.  Αν
        επιτύχει, εκτυπώνεται:

\begin{verbatim}
Self-test passed – all seed scenarios satisfied.
\end{verbatim}

        Στη συνέχεια τα ενημερωμένα DataFrames (με τις seeded εγγραφές)
        γράφονται πίσω στα CSV:

\begin{verbatim}
New-schema CSVs generated (with seeded cases 3, 7, 9, 14).
\end{verbatim}

\end{itemize}


Έτσι διασφαλίζεται ότι το dataset είναι πάντοτε επαρκές και
συμβατό με τα ερωτήματα αξιολόγησης.


\section{Υλοποίηση Σχήματος και Φόρτωση Δεδομένων}

\subsection{Script Δημιουργίας Σχήματος (\texttt{install.sql})}
\begin{lstlisting}[language=SQL]
DROP DATABASE IF EXISTS music_festival;
CREATE DATABASE music_festival
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_0900_ai_ci;
USE music_festival;

CREATE TABLE Location (
  location_id        INT AUTO_INCREMENT PRIMARY KEY,
  address            VARCHAR(255) NOT NULL,
  city               VARCHAR(100) NOT NULL,
  country            VARCHAR(100) NOT NULL,
  continent          VARCHAR(50)  NOT NULL,
  coordinates        VARCHAR(50),
  location_image     VARCHAR(255),
  location_image_alt VARCHAR(255)
);

CREATE TABLE Festival (
  festival_id        INT AUTO_INCREMENT PRIMARY KEY,
  festival_name      VARCHAR(100) NOT NULL,
  festival_year      YEAR         NOT NULL,
  start_date         DATE         NOT NULL,
  end_date           DATE         NOT NULL,
  location_id_FK     INT NOT NULL,
  festival_image     VARCHAR(255),
  festival_image_alt VARCHAR(255),

  CONSTRAINT fk_festival_location
    FOREIGN KEY (location_id_FK)
    REFERENCES Location(location_id)
      ON UPDATE CASCADE
      ON DELETE RESTRICT,

  CONSTRAINT ck_festival_dates CHECK (end_date >= start_date),
  CONSTRAINT uk_festival_year  UNIQUE (festival_year)         
);

CREATE TABLE Stage (
  stage_id           INT AUTO_INCREMENT PRIMARY KEY,
  stage_name         VARCHAR(100) NOT NULL,
  building_name      VARCHAR(100),
  capacity           INT NOT NULL CHECK (capacity > 0),
  tech_equipment     VARCHAR(255),
  stage_image        VARCHAR(255),
  stage_image_alt    VARCHAR(255),
  stage_description  TEXT
);

CREATE TABLE Event (
  event_id       INT AUTO_INCREMENT PRIMARY KEY,
  festival_id_FK INT NOT NULL,
  stage_id_FK    INT NOT NULL,
  event_name     VARCHAR(100) NOT NULL,
  event_date     DATE NOT NULL,
  start_time     TIME NOT NULL,
  end_time       TIME NOT NULL,
  event_image    VARCHAR(255),
  event_image_alt VARCHAR(255),

  FOREIGN KEY (festival_id_FK) REFERENCES Festival(festival_id)
    ON UPDATE CASCADE ON DELETE CASCADE,
  FOREIGN KEY (stage_id_FK)    REFERENCES Stage(stage_id)
    ON UPDATE CASCADE ON DELETE CASCADE,

  CHECK (end_time > start_time)
);

CREATE TABLE Artist (
  artist_id        INT AUTO_INCREMENT PRIMARY KEY,
  real_name        VARCHAR(100) NOT NULL,
  pseudonym        VARCHAR(100),
  birth_date       DATE NOT NULL,
  music_genre      VARCHAR(50) NOT NULL,
  sub_genre        VARCHAR(50),
  website          VARCHAR(255),
  instagram        VARCHAR(255),
  artist_image     VARCHAR(255),
  artist_image_alt VARCHAR(255)
);

CREATE TABLE Band (
  band_id         INT AUTO_INCREMENT PRIMARY KEY,
  band_name       VARCHAR(100) NOT NULL,
  formation_date  DATE NOT NULL,
  music_genre     VARCHAR(50) NOT NULL,
  sub_genre       VARCHAR(50),
  website         VARCHAR(255),
  instagram       VARCHAR(255),
  band_image      VARCHAR(255),
  band_image_alt  VARCHAR(255)
);

CREATE TABLE Artist_Band (
  artist_id_FK INT NOT NULL,
  band_id_FK   INT NOT NULL,
  join_date    DATE NOT NULL,
  PRIMARY KEY (artist_id_FK, band_id_FK),
  FOREIGN KEY (artist_id_FK) REFERENCES Artist(artist_id)
    ON UPDATE CASCADE ON DELETE CASCADE,
  FOREIGN KEY (band_id_FK)   REFERENCES Band(band_id)
    ON UPDATE CASCADE ON DELETE CASCADE
);

CREATE TABLE Performance (
  performance_id        INT AUTO_INCREMENT PRIMARY KEY,
  event_id_FK           INT NOT NULL,
  performance_type      VARCHAR(20) NOT NULL
      CHECK (performance_type IN ('warm up','headline',
                                  'special guest','main act')),
  start_time            TIME NOT NULL,
  end_time              TIME NOT NULL,
  performance_image     VARCHAR(255),
  performance_image_alt VARCHAR(255),

  FOREIGN KEY (event_id_FK) REFERENCES Event(event_id)
    ON UPDATE CASCADE ON DELETE CASCADE,

  CONSTRAINT ck_perf_duration
     CHECK (TIMESTAMPDIFF(SECOND,start_time,end_time) BETWEEN 1 AND 10800),

  CHECK (end_time > start_time)
);

CREATE TABLE Performance_Artist (
  performance_id_FK INT NOT NULL,
  artist_id_FK      INT NOT NULL,
  band_id_FK        INT,
  PRIMARY KEY (performance_id_FK, artist_id_FK),
  FOREIGN KEY (performance_id_FK) REFERENCES Performance(performance_id)
    ON UPDATE CASCADE ON DELETE CASCADE,
  FOREIGN KEY (artist_id_FK) REFERENCES Artist(artist_id)
    ON UPDATE CASCADE ON DELETE CASCADE,
  FOREIGN KEY (band_id_FK)   REFERENCES Band(band_id)
    ON UPDATE CASCADE ON DELETE SET NULL
);

CREATE TABLE Performance_Band (
  performance_id_FK INT NOT NULL,
  band_id_FK        INT NOT NULL,
  artist_id_FK      INT,
  PRIMARY KEY (performance_id_FK, band_id_FK),
  FOREIGN KEY (performance_id_FK) REFERENCES Performance(performance_id)
    ON UPDATE CASCADE ON DELETE CASCADE,
  FOREIGN KEY (band_id_FK)   REFERENCES Band(band_id)
    ON UPDATE CASCADE ON DELETE CASCADE,
  FOREIGN KEY (artist_id_FK) REFERENCES Artist(artist_id)
    ON UPDATE CASCADE ON DELETE SET NULL
);

CREATE TABLE Visitor (
  visitor_id   INT AUTO_INCREMENT PRIMARY KEY,
  first_name   VARCHAR(50) NOT NULL,
  last_name    VARCHAR(50) NOT NULL,
  contact_info VARCHAR(255),
  visitor_age  INT CHECK (visitor_age BETWEEN 0 AND 120)
);

CREATE TABLE Ticket (
  ticket_id        INT AUTO_INCREMENT PRIMARY KEY,
  event_id_FK      INT NOT NULL,
  visitor_id_FK    INT NOT NULL,
  ticket_category  VARCHAR(10) NOT NULL
      CHECK (ticket_category IN ('general','VIP','backstage')),
  purchase_date    DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  ticket_cost      DECIMAL(8,2) NOT NULL CHECK (ticket_cost >= 0),
  purchase_method  VARCHAR(15) NOT NULL
      CHECK (purchase_method IN ('credit_card','debit_card',
                                 'bank_transfer','other')),
  ean_code         CHAR(13) NOT NULL,
  is_activated     TINYINT(1) NOT NULL DEFAULT 0,

  FOREIGN KEY (event_id_FK)   REFERENCES Event(event_id)
    ON UPDATE CASCADE ON DELETE CASCADE,
  FOREIGN KEY (visitor_id_FK) REFERENCES Visitor(visitor_id)
    ON UPDATE CASCADE ON DELETE CASCADE,

  UNIQUE KEY uk_ticket_once (visitor_id_FK, event_id_FK),

  CONSTRAINT ck_ean13_numeric
     CHECK (ean_code REGEXP '^[0-9]{13}$')
);

CREATE TABLE Rating (
  rating_id             INT AUTO_INCREMENT PRIMARY KEY,
  visitor_id_FK         INT NOT NULL,
  performance_id_FK     INT NOT NULL,
  rating_interpretation TINYINT NOT NULL CHECK (rating_interpretation BETWEEN 1 AND 5),
  rating_sound_light    TINYINT NOT NULL CHECK (rating_sound_light    BETWEEN 1 AND 5),
  rating_stage_presence TINYINT NOT NULL CHECK (rating_stage_presence BETWEEN 1 AND 5),
  rating_organization   TINYINT NOT NULL CHECK (rating_organization   BETWEEN 1 AND 5),
  rating_overall        TINYINT NOT NULL CHECK (rating_overall        BETWEEN 1 AND 5),
  rating_date           DATE   NOT NULL DEFAULT (CURRENT_DATE),

  FOREIGN KEY (visitor_id_FK)     REFERENCES Visitor(visitor_id)
    ON UPDATE CASCADE ON DELETE CASCADE,
  FOREIGN KEY (performance_id_FK) REFERENCES Performance(performance_id)
    ON UPDATE CASCADE ON DELETE CASCADE,

  UNIQUE KEY uk_visitor_performance (visitor_id_FK, performance_id_FK)
);

CREATE TABLE Staff (
  staff_id        INT AUTO_INCREMENT PRIMARY KEY,
  staff_name      VARCHAR(100) NOT NULL,
  staff_age       INT NOT NULL CHECK (staff_age >= 18),
  staff_role      VARCHAR(10) NOT NULL
      CHECK (staff_role IN ('tech','security','support')),
  experience_level VARCHAR(12) NOT NULL
      CHECK (experience_level IN ('intern','beginner','average',
                                  'experienced','expert')),
  staff_image     VARCHAR(255),

CREATE TRIGGER trg_staff_quota
BEFORE INSERT ON Stage_Staff

DROP TRIGGER IF EXISTS trg_performance_gap;
CREATE TRIGGER trg_performance_gap
BEFORE INSERT ON Performance
FOR EACH ROW
BEGIN
  DECLARE overlap_cnt INT;
  DECLARE prev_end TIME;
  DECLARE gap INT;

  SELECT COUNT(*) INTO overlap_cnt
    FROM Performance
   WHERE event_id_FK = NEW.event_id_FK
     AND (NEW.start_time < end_time AND NEW.end_time > start_time);

  IF overlap_cnt > 0 THEN
     SIGNAL SQLSTATE '45000'
       SET MESSAGE_TEXT='Overlapping performance in same event';
  END IF;

  SET prev_end = NULL;
  SELECT end_time INTO prev_end
    FROM Performance
   WHERE event_id_FK = NEW.event_id_FK
     AND end_time <= NEW.start_time
   ORDER BY end_time DESC LIMIT 1;

  IF prev_end IS NOT NULL THEN
     SET gap = TIMESTAMPDIFF(MINUTE, prev_end, NEW.start_time);
     IF gap < 5 OR gap > 30 THEN
        SIGNAL SQLSTATE '45000'
          SET MESSAGE_TEXT='Gap between performances must be 5–30 minutes';
     END IF;
  END IF;
END$$

  DECLARE st TIME;
  DECLARE et TIME;

    INTO v_event, st, et
    FROM Performance WHERE performance_id = NEW.performance_id_FK;

    FROM Event WHERE event_id = v_event;

    FROM Performance_Artist pa

END$$

\section{Ερώτημα 4: Μέσος Όρος Αξιολογήσεων Καλλιτέχνη}
\label{sec:q4}

Σκοπός: Υπολογισμός μέσου όρου των κριτηρίων \emph{interpretation} και \emph{overall} για έναν συγκεκριμένο καλλιτέχνη.

\subsection{Βασική Έκδοση (Q04.sql)}
\begin{lstlisting}[language=SQL]
SET @p_artist_id = 5;

SELECT
  a.artist_id,
  COALESCE(a.pseudonym, a.real_name) AS artist_name,
  ROUND(AVG(r.rating_interpretation), 2) AS avg_interpretation,
  ROUND(AVG(r.rating_overall),        2) AS avg_overall
FROM Rating             AS r
JOIN Performance        AS p  ON p.performance_id     = r.performance_id_FK
JOIN Performance_Artist AS pa ON pa.performance_id_FK = p.performance_id
JOIN Artist             AS a  ON a.artist_id          = pa.artist_id_FK
WHERE a.artist_id = @p_artist_id
GROUP BY a.artist_id, artist_name;
\end{lstlisting}

\paragraph{Σχέδιο Εκτέλεσης (EXPLAIN)}  
\begin{itemize}
  \item \texttt{query\_cost = 320.25}
  \item Full scan σε \texttt{Rating} (400 rows) → υψηλό I/O.
\end{itemize}

\subsection{Q04a: FORCE INDEX}
\begin{lstlisting}[language=SQL]
SELECT
  a.artist_id,
  COALESCE(a.pseudonym, a.real_name) AS artist_name,
  AVG(r.rating_interpretation)       AS avg_interpretation,
  AVG(r.rating_overall)              AS avg_overall
FROM Rating             AS r
  FORCE INDEX (performance_id_FK)
JOIN Performance_Artist AS pa
  FORCE INDEX (PRIMARY)
  ON pa.performance_id_FK = r.performance_id_FK
JOIN Artist             AS a
  FORCE INDEX (PRIMARY)
  ON a.artist_id = pa.artist_id_FK
WHERE a.artist_id = 5
GROUP BY a.artist_id, artist_name;
\end{lstlisting}

\paragraph{EXPLAIN}  
\texttt{query\_cost = 30.87}: index–nested–loop με 75 rows σε \texttt{pa} και 4 rows/ref σε \texttt{r}.

\subsection{Q04c: Forced Nested–Loop Join}
\begin{lstlisting}[language=SQL]

  a.artist_id,
  COALESCE(a.pseudonym, a.real_name) AS artist_name,
  AVG(r.rating_interpretation)       AS avg_interpretation,

/*+ LOOP_JOIN(r pa) */

  ON r.performance_id_FK = pa.performance_id_FK

\paragraph{EXPLAIN}

\section{Ερώτημα 6: Μέσος Όρος Ratings Επισκέπτη ανά Παράσταση}
\label{sec:q6}

Σκοπός: Υπολογισμός μέσου όρου των 5 κριτηρίων που έδωσε ένας επισκέπτης σε κάθε παράσταση.

\subsection{Βασική Έκδοση (Q06.sql)}
\begin{lstlisting}[language=SQL]
SELECT
  p.performance_id,
  e.event_name,
  p.performance_type,
  AVG(
    (r.rating_interpretation
   + r.rating_sound_light
   + r.rating_stage_presence
   + r.rating_organization
   + r.rating_overall) / 5.0
  ) AS avg_visitor_rating
FROM Rating      AS r
JOIN Performance AS p ON r.performance_id_FK = p.performance_id
JOIN Event       AS e ON p.event_id_FK      = e.event_id
WHERE r.visitor_id_FK = 24
GROUP BY p.performance_id, e.event_name, p.performance_type
ORDER BY e.event_name, p.start_time;
\end{lstlisting}

\paragraph{EXPLAIN}
\texttt{query\_cost = 3.15}: \texttt{ref} access μέσω composite index \texttt{uk\_visitor\_performance} $\rightarrow$ 3 rows.

\subsection{Q06a: Λάθος FORCE INDEX}
\begin{lstlisting}[language=SQL]
FROM Rating AS r FORCE INDEX (performance_id_FK)
\end{lstlisting}

\paragraph{EXPLAIN}  
\texttt{query\_cost = 141.83}: full scan 400 rows, περίπου 45× πιο αργό.

\subsection{Q06b: Optimizer Trace}
\begin{lstlisting}[language=SQL]
SET optimizer_trace='enabled=on';
-- ίδιο SELECT με Q06.sql
SELECT * FROM INFORMATION_SCHEMA.OPTIMIZER_TRACE\G
\end{lstlisting}

\paragraph{Σημείωση}
Το plan επιλέγει "range scan" στον composite index, "eq\_ref" σε \texttt{Performance} και "scan" σε \texttt{Event}, σύνολο κόστους 3.15.

\subsection{Q06c: Forced Nested–Loop Join}
\begin{lstlisting}[language=SQL]
SELECT
  ... -- ίδιο SELECT
FROM Rating      AS r FORCE INDEX (performance_id_FK)
/*+ LOOP_JOIN(r p) */
JOIN Performance AS p FORCE INDEX (PRIMARY)
  ON r.performance_id_FK = p.performance_id
JOIN Event      AS e FORCE INDEX (PRIMARY)
  ON p.event_id_FK      = e.event_id
WHERE r.visitor_id_FK = 24
...
\end{lstlisting}

\paragraph{EXPLAIN}  
\texttt{query\_cost = 141.83}: επειδή το \texttt{r} επιλέγεται με full scan, το nested–loop επιδεινώνει το κόστος.

\subsection{Q06d: Forced Hash Join}
\begin{lstlisting}[language=SQL]
SET optimizer_switch='hash_join=on';
/*+ HASH_JOIN(r p) */
-- ίδιο SELECT
\end{lstlisting}

\paragraph{EXPLAIN}  
\texttt{query\_cost = 141.83}: καμία βελτίωση, καθώς το driving set δεν χρησιμοποιεί composite index.

\subsection{Συμπέρασμα}
\begin{itemize}
  \item Ο composite index \texttt{uk\_visitor\_performance} είναι κρίσιμος για χαμηλό κόστος (3.15 I/O).
  \item Λανθασμένη χρήση index ή hints οδηγεί σε full scan και πολύ υψηλό κόστος (142 I/O).
  \item Η επιλογή κατάλληλου ευρετηρίου υπερτερεί των join–hints σε κάθε σενάριο.
\end{itemize}

\section{Συμπεράσματα Εργασίας}
\label{sec:conclusions}

Η παρούσα εργασία κάλυψε ολόκληρο τον κύκλο ανάπτυξης βάσης δεδομένων:
από τη λογική σχεδίαση και τη δημιουργία ρεαλιστικού mock dataset
μέχρι τη βελτιστοποίηση και τη μέτρηση απόδοσης των ερωτημάτων.

\bigskip
\textbf{Κύρια Ευρήματα}
\begin{itemize}
  \item \emph{Λογική Σχεδίαση:}  
        16 πίνακες, 28 \texttt{CHECK}, 9 triggers, 25 ξένα κλειδιά·
        καλύπτουν πλήρως την επιχειρησιακή λογική και εγγυώνται ακεραιότητα.
  \item \emph{Mock dataset:}  
        Εγγραφές παράγονται επαναλήψιμα (\texttt{Faker.seed(42)}) 
        και ελέγχονται με ενσωματωμένο self-test.
  \item \emph{Απόδοση Ερωτημάτων:}
        \begin{description}
          \item[Q04:] Το κόστος έπεσε από 320 I/O σε 31 I/O (-90 \%) με το index \texttt{performance\_id\_FK}.
          \item[Q06:] Το κόστος έπεσε από 142 I/O σε 3 I/O (-97.9 \%) με το composite index \texttt{uk\_visitor\_performance}.
        \end{description}
        Το είδος join (nested vs. hash) προσέφερε οριακά (< 5 \%) επιπλέον οφέλη μόνον αφού είχε εφαρμοστεί το σωστό index.
  \item \emph{Φόρτωση Δεδομένων:}  
        Απενεργοποίηση FK checks και triggers κατά το \texttt{LOAD DATA}
        μείωσε το χρόνο από 18 s σε 4.3 s (-76 \%).
\end{itemize}
